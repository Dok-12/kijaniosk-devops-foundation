KijaniKiosk Week 5 Friday — Credential Audit
=============================================

Scope
-----
Reviewed Jenkinsfile credential references, Git ignore rules, tracked
filenames, selected Git history patterns, and the Jenkins pipeline output.

Jenkins credential handling
---------------------------
- The publish stage uses the Jenkins credential ID: nexus-publisher.
- Username and password are injected as NEXUS_USER and NEXUS_PASSWORD.
- Shell tracing is disabled with set +x before credential-sensitive commands.
- A temporary .npmrc is created for authenticated publishing.
- The Jenkinsfile defines cleanup for the temporary .npmrc and removes it
  after publishing; the pipeline also runs cleanWs() in its post actions.
- The credential value itself is not stored in this evidence file.

Repository checks
-----------------
- .gitignore excludes .env, .npmrc, and *.log.
- The tracked-file search returned no filenames matching .env, .npmrc,
  credentials, or secrets naming patterns.
- The Git history filename search found no .env or .npmrc entries.
- A pattern-based scan of Jenkinsfile, package.json, and .gitignore found
  no matches for the checked hard-coded-secret assignment patterns.
- This targeted scan does not guarantee that every possible secret is
  absent from all files or historical commits..

Pipeline evidence
-----------------
- The publish stage was restored after the intentional publish-failure test.
- The final restoration run completed successfully and published
  kijanikiosk-payments@1.0.0-487e2e3 to the configured Nexus npm repository.
- The pipeline console reported credential masking and the publish command
  used set +x. No credential values are reproduced in this report.

Limitations and recommendation
------------------------------
These checks are targeted safeguards, not proof that every possible secret
has been eliminated from every file or every historical commit. Keep
publishing credentials in Jenkins Credentials, avoid committing real
credentials, review any flagged historical matches locally, and rotate a
credential if exposure is confirmed.
